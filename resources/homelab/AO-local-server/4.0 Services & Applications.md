## 4.3 Application Stacks
### 4.3.1 Core utilities Stack
This stack comprises the essential management and support services that underpin the entire server's operation.
- **Homepage:** A customisable dashboard providing central access to all service UIs.
- **Portainer:** A web UI for managing the Docker environment.
- **AdGuard Home:** The network-wide DNS sinkhole for ad-blocking.
- **Watchtower:** A service that automatically monitors and updates running Docker containers to their latest versions.
- **Apprise:** A centralised notification dispatcher that allows other services to send alerts via multiple platforms.
**Key Configuration Pattern:**
- The `docker-compose.yml` for this stack is located at `C:\server\config\core-utilities\`.
- A key post-deployment step is editing the `docker.yaml` file in Homepage's appdata volume to connect it to a Docker proxy for displaying container information.

### 4.3.2 Personal cloud stack
This stack provides a suite of services designed to replace commercial cloud offerings for file management, photo backup, and document archiving.
- **Nextcloud:** The primary file sync, calendar, and contacts hub.
- **Collabora Online:** An online office suite integrated with Nextcloud for live document editing.
- **Immich:** A high-performance photo and video backup and management solution, acting as a replacement for Google Photos.
- **Paperless-ngx:** A document management system that archives, indexes, and OCRs scanned documents.
**Key Integration Patterns:**
- Nextcloud's "External Storage" application is used to provide read-only access to the data libraries of Paperless-ngx and Immich, creating a unified view.
- The detailed process for integrating Collabora with Nextcloud will be documented in `[[Configuring Nextcloud and Collabora]]`.

### 4.3.3 Media Stack
This stack automates the acquisition, organisation, and streaming of media content. It employs two parallel workflows for music to balance automation with quality control.
**Core Components:**
- **Jellyfin:** The central media server for streaming video and audio content.
- *_The _arr Suite:__ (Sonarr, Radarr, Lidarr, Bazarr, Prowlarr) A suite of applications for the automated monitoring, downloading, and organising of media.
- **Navidrome:** A lightweight music server for streaming the music library.
- **Jellyseerr:** A user-facing request management system for media.
- **Transmission & Gluetun:** The torrent download client, containerised with a VPN killswitch for security.
- **Unmanic:** An automated file transcoder for library optimisation.
**Acquisition Pipelines:**
1. **Automated Pipeline:** The *arr suite provides a "set and forget" workflow for general media.
2. **High-Quality Music Pipeline:** `slskd` (Soulseek) is used for manually sourcing rare or high-fidelity music, which is then processed, tagged, and organised by `Beets`.
**Key Configuration Pattern:**
- To enable zero-copy moves (hardlinking), the entire `C:\server\data` directory is mounted as `/data` within each *arr container. Specific paths are then configured inside each application's UI. This will be detailed in the `[[Media Management Workflow]]`.

### 4.3.4 Web server stack
This stack uses a central NGINX container as a reverse proxy to serve multiple static websites from a single entry point (`http://ao:8090`). This allows for the simple addition of new sites without exposing additional ports.
**Architectural Components:**
- **`docker-compose.yml`:** Located at `C:\server\config\nginx-proxy\`, this file defines the primary NGINX proxy container as well as a service for each static site.
- **`default.conf`:** The main NGINX configuration file, located in the same directory. It contains the routing rules (`server` blocks) that direct traffic to the correct website container based on the requested hostname.
- **Website Data:** All static site files are stored in subdirectories within `C:\server\data\sites\`.
**Deployment Process:**
- The full, step-by-step process for adding a new site to the proxy is documented in `[[Deploying a New Static Website]]`.
