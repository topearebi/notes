## 5.1 Goal-Oriented Workflows
### Media Management Workflow
This workflow details the automated and manual pipelines for acquiring, organising, and consuming video and music content.
### Video Acquisition Pipeline
This is a fully automated process, triggered by a user request.
**Process Flow:**
```
graph TD
    A[Request in Jellyseerr] --> B[*arr Apps];
    B --> C[Prowlarr];
    C --> D[Transmission on VPN];
    D --> E[Downloaded to C:\server\data\torrents];
    E --> F{*arr Apps Process & Hardlink};
    F --> G[File appears in C:\server\data\media];
    G --> H[Available in Jellyfin];
```
**Steps:**
1. **Request:** A user requests a movie or TV show using the Jellyseerr interface.
2. **Acquire:** Jellyseerr passes the request to the appropriate *arr application (Sonarr/Radarr). The *arr app searches configured indexers via Prowlarr and sends the chosen download to Transmission.
3. **Process:** Once the download is complete in `C:\server\data\torrents`, the *arr app creates a hardlink of the file, renames it according to library standards, and moves the link to the final media library at `C:\server\data\media`.
4. **Consume:** Jellyfin automatically detects the new file and makes it available for streaming.
### Music Acquisition Pipelines
Two distinct pipelines are used for music to balance broad automation with manual acquisition of high-quality or rare tracks.
**1. Automated Pipeline (Lidarr)**
```
graph TD
    A[Artist Monitored in Lidarr] --> B[Prowlarr];
    B --> C[Transmission on VPN];
    C --> D[Downloaded to C:\server\data\torrents\music];
    D --> E{Lidarr Processes & Moves};
    E --> F[File appears in C:\server\data\media\music];
    F --> G[Available in Navidrome];
```

**2. High-Quality / Manual Pipeline (Beets & slskd)**
```
graph TD
    A[Manual Search in slskd] --> B{Download};
    B --> C[Downloaded to C:\server\data\torrents\slskd-downloads];
    C --> D{Beets Imports, Tags & Moves};
    D --> E[File appears in C:\server\data\media\music];
    E --> F[Available in Navidrome];
```
### Document Archiving Workflow
This workflow outlines the end-to-end process for converting a physical paper document into a searchable, archived digital file.
**Process Flow:**
```
graph TD
    A[Physical Document] --> B{Scan with Nextcloud App};
    B --> C["Save to 'Scans for Paperless' folder"];
    C --> D[C:\server\data\consume];
    D --> E{Paperless-ngx Ingests & Processes};
    E --> F[C:\server\data\documents];
    F --> G{Manage in Paperless-ngx UI};
    F --> H{Browse/Share via Nextcloud Read-Only Mount};
```
**Steps:**
1. **Scan:** Use the document scanning feature within the Nextcloud mobile application to capture the physical document as a PDF.
2. **Ingest:** Save the resulting PDF file directly into the designated `Scans for Paperless` folder within Nextcloud. This folder is monitored by Paperless-ngx.
3. **Process:** Paperless-ngx automatically consumes the file from the monitored folder, performs Optical Character Recognition (OCR), applies tags based on defined rules, and archives it.
4. **Manage:** Use the Paperless-ngx web interface for advanced searching, tagging, and organisation of the archived documents.
5. **Access & Share:** For general browsing or sharing, access the final files via the read-only `Document Archive` folder in Nextcloud.
### Photo Management Workflow
This workflow describes the process for automatically backing up photos and videos from mobile devices and sharing them securely.
**Process Flow:**
```
graph TD
    A[Phone Camera] --> B{Immich Mobile App};
    B --> C{Immich Server};
    C --> D[C:\server\data\photos];
    D --> E{Manage in Immich UI};
    D --> F{Browse/Share via Nextcloud Read-Only Mount};
```
**Steps:**
1. **Upload:** The Immich mobile application automatically detects and uploads new photos and videos to the Immich server.
2. **Manage:** Use the Immich web UI or mobile app to interact with the media library. This includes viewing the timeline, searching for objects or faces, and creating shared albums for other Immich users on the server.
3. **Share Externally:** To share photos or albums with individuals who do not have an Immich account, use the Nextcloud interface. Browse the read-only `Family Photo Library` external share and use Nextcloud's functionality to create secure, public, password-protected links.
### E-Book Acquisition Workflow

This workflow uses a dedicated web UI to search for and download e-books, which are then automatically processed and added to the main library.
**Process Flow:**

```
graph TD
    A[Search in Book Downloader UI] --> B{Request Download};
    B --> C[Downloader saves file to C:\server\data\consume\books];
    C --> D{Calibre-Web Automated Ingests & Processes};
    D --> E[File appears in C:\server\data\books];
    E --> F[Available in Calibre-Web Automated];
```
**Steps:**
1. **Request**: A user searches for a book in the **Book Downloader** web interface (`http://ao:8084`) and requests a download.
2. **Acquire**: The downloader service finds a suitable version and downloads the file directly to the dedicated ingest folder at `C:\server\data\consume\books`.
3. **Process**: The main **Calibre-Web Automated** service automatically detects the new file in the ingest folder. It performs any required conversions, fixes metadata, and moves the final, processed e-book into the main library at `C:\server\data\books`.
4. **Consume**: The new book is immediately available to read via the Calibre-Web Automated interface at `http://ao:8083`.
