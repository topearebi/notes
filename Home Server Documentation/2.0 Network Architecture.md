## 2.3 DNS and Ad-Blocking
DNS resolution on the local network is managed by an instance of AdGuard Home running on the server. This provides network-wide ad-blocking and local name resolution.
### AdGuard Home Configuration Strategy
The primary router's DNS settings are **not** modified. Instead, ad-blocking is enabled on a per-device basis by manually configuring each client to use the server's IP address for DNS.
- **AdGuard Home IP:** `192.168.1.104`
- **Deployment Method:** `[Placeholder for AdGuard Home deployment method, e.g., Docker container]`
- **Configuration Volume Path:** `[Placeholder for path, e.g., C:\server\appdata\adguardhome]`
### Client and Server DNS Settings
- **Server Self-Resolution:** The server itself is configured in Windows to use `127.0.0.1` (localhost) as its DNS server, forcing it to resolve through its own AdGuard Home instance.
- **Client Configuration:** Individual devices (e.g., mobile phones, laptops) are configured in their respective network settings to use the server's static IP, `192.168.1.104`, as their sole DNS server.
### Tailscale DNS Integration
To allow devices on the local network to resolve hostnames of devices within the Tailscale VPN (e.g., `ao`), the Tailscale DNS server is configured within AdGuard Home.
- **Configuration:** The IP `100.100.100.100` is added to the "Upstream DNS servers" list in the AdGuard Home settings.
